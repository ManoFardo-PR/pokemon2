## Initial objective
Every boundary between processes and languages is described once as a zod schema with an exported JSON Schema, so the API, worker, ETL and Rust engine agree on shapes by construction instead of by convention.

## Context

Architecture principle 9 requires every process or language boundary to be a zod schema with an exported JSON Schema and a version. This subtask creates the place those schemas live, before any of them has content — deliberately, because D-001's gate ([S01.T06](T06-rust-toolchain-gate.md)) may replace Rust with TypeScript, and the decision log states that "all boundaries are therefore defined in `packages/shared` first". With the boundaries fixed and language-neutral, the engine's implementation language becomes an internal detail.

The legacy project had a partial version of the idea: `pokemon/src/pokesearch/search/filters.py` defines `SearchQuery` as a pydantic model whose field descriptions doubled as the JSON schema handed to the LLM. It existed on one side of one boundary; the simulator boundary was in-process Python objects and monkeypatches. Here there are four boundaries that cross a process or a language — api ⇄ web, worker ⇄ engine, etl ⇄ loaders, and the scenario/IR files git stores and the engine reads — and each gets a folder.

What ships now is the skeleton plus the machinery: layout, export pipeline, version rule, the tests that make the pipeline trustworthy, and one minimal but real placeholder per contract so consumers can import something today. Each later subtask replaces its own placeholder.

## Scope

- **In scope.** `packages/shared/src/` layout and barrel exports; `CONTRACT_VERSION` and its rule; one placeholder schema per contract with its inferred type and a sample; the JSON Schema exporter and its determinism check; `CONTRACTS.md`; the "pure package" constraints; moving `env.ts` under `src/` as the one module allowed to read `process.env`.
- **Out of scope.** The content of any contract (each named subtask below); the Rust `serde` structs and their diff against the JSON Schema ([S04.T12](../04-game-engine-core/T12-cli-job-protocol.md)); the pure helpers that will live here later — NL parser ([S02.T10](../02-card-data-and-search/T10-natural-language-parser.md)), decklist parser ([S03.T09](../03-tournament-meta-and-deck-builder/T09-decklist-parser-and-exporter.md)), deck validation ([S03.T10](../03-tournament-meta-and-deck-builder/T10-deck-validation-rules.md)) — whose folders are only reserved; the Fastify type-provider wiring ([S01.T07](T07-api-skeleton-and-health.md)).

## Business rules

The traceability doc assigns no `RN-nn` here. Two later rules depend on this machinery: RN-61 (LLM output becomes behaviour only through a closed, schema-validated vocabulary) via [S05.T03](../05-card-rules-base/T03-effect-ir-vocabulary.md), and RN-10 (60-card decks) via [S03.T10](../03-tournament-meta-and-deck-builder/T10-deck-validation-rules.md); both inherit the strictness rules below.

| ID | Rule | Enforcement point | Verification |
|---|---|---|---|
| BR-S01.T05-01 | The package is pure: no `node:*` import, no I/O, no database, no framework — the single exception is `src/env.ts`, never imported by browser code. | eslint `no-restricted-imports` with a file-level override; zod is the only dependency | `pnpm lint`; `pnpm --filter web build` succeeds with no Node polyfill and no `env.ts` in the bundle |
| BR-S01.T05-02 | Every exported top-level schema has exactly one file in `packages/shared/schema/`, and vice versa. | `schema:build` writes from the `CONTRACTS` registry | `contracts.spec.ts > registry and schema directory agree` |
| BR-S01.T05-03 | Regenerating the JSON Schema files is byte-identical (sorted keys, 2-space indent, trailing newline). | deterministic stringifier in `schema:build`; `schema:check` regenerates into a temp dir and diffs | `pnpm --filter @pokesearch/shared schema:check` exits 0 twice in a row; runs inside `pnpm check` |
| BR-S01.T05-04 | Every schema is strict: an unknown key fails `parse`. Forward compatibility comes from a version bump, never from ignoring fields. | `.strict()` on every object schema | `contracts.spec.ts > every contract rejects unknown keys` |
| BR-S01.T05-05 | Every contract sample round-trips through `JSON.parse(JSON.stringify(x))`; no `Date`, `BigInt`, `undefined` or `Map` appears in any contract. | the registry requires a `sample`; a spec walks the schema tree and bans those types | `contracts.spec.ts > round-trip per contract`, `> no non-JSON types` |
| BR-S01.T05-06 | Removing or renaming a field, narrowing a type or changing a discriminator bumps the major of `CONTRACT_VERSION` and adds a CONTRACTS.md changelog row; an additive optional field bumps the minor. | review checklist; every JSON Schema `$id` carries the current major | `contracts.spec.ts > $id major matches CONTRACT_VERSION`; the committed schema diff makes the change visible in review |
| BR-S01.T05-07 | Every field carries an English `.describe()` that survives into the JSON Schema. | schema authoring; a spec listing undescribed fields | `contracts.spec.ts > every field is described` |
| BR-S01.T05-08 | Every union crossing a process boundary is discriminated by a string tag (`type` for stream events, `kind` for jobs), so `serde` can mirror it with `#[serde(tag = "…")]`. | `z.discriminatedUnion` only | `contracts.spec.ts > boundary unions are tagged` |

## Interfaces

**Exports map**: `.`, `./env`, `./search`, `./decklist`, `./ir`, `./jobs`, `./scenario`, `./card-def`. Subpath exports keep `env.ts` out of the web bundle.

```ts
// src/version.ts
export const CONTRACT_VERSION = "1.0.0" as const;
export const CONTRACT_MAJOR = 1 as const;
export function isCompatible(other: string): boolean;   // same major
```

The engine refuses a job whose `contractVersion` major differs, answering one `{"type":"error","code":"contract_major_mismatch"}` line ([S04.T12](../04-game-engine-core/T12-cli-job-protocol.md)).

**Registry and export.** `src/registry.ts` exports `CONTRACTS: readonly { name, schema, sample, file }[]`. `schema:build` walks it, exports each schema as JSON Schema draft 2020-12, sets `$id = "https://pokesearch.invalid/schema/v<major>/<file>"`, carries `title`/`description` from the zod descriptions, and writes with sorted keys. `schema:check` regenerates into a temp directory and fails on any diff. zod is pinned once at the workspace root (pnpm `overrides`) so two copies can never produce two incompatible `ZodType` identities.

**`CONTRACTS.md` outline.** (1) What a contract is and the four boundaries. (2) The rules: strict objects, described fields, discriminated unions, JSON-only types. (3) `CONTRACT_VERSION` semantics with a major/minor decision table. (4) How the engine handshake uses it. (5) Adding a contract: registry entry, sample, schema file, changelog row. (6) The changelog table.

## Edge cases and error handling

- **Two copies of zod in the tree** → `instanceof` checks fail and Fastify's type provider silently stops validating. Prevention: one pinned version through pnpm `overrides` plus a spec asserting single resolution; the failure mode is documented in CONTRACTS.md.
- **A schema uses `z.date()`, `z.bigint()`, `z.map()` or `z.undefined()`** → the JSON Schema export loses information and `serde` cannot mirror it. The tree-walking spec fails the build and names the field; timestamps are ISO-8601 strings, as in the data model.
- **A `z.union` without a discriminator crosses the engine boundary** → `serde` would need untagged deserialisation, which silently picks the first match. Rejected by BR-S01.T05-08.
- **`schema:check` fails only on CI** (key order, line endings) → the serialiser sorts keys and writes `\n`; `.gitattributes` marks `packages/shared/schema/*.json` as `text eol=lf`.
- **A later subtask needs an additive field urgently** → minor bump, optional field with a default; the engine's major check still passes and the changelog records it. Removing a field is never urgent enough to skip the major bump.
- **The IR placeholder blocks an early experiment** → intended: an IR op is introduced through [S05.T03](../05-card-rules-base/T03-effect-ir-vocabulary.md)'s closed vocabulary (RN-61), not smuggled in from a consumer.
- **A description written in pt-BR** → rejected by the description spec; D-006 keeps the repository English, and user-visible pt-BR lives in the web strings module.

## Risks and open questions

- **Risk — zod's JSON Schema output cannot express something the Rust side needs** (`.refine()` predicates are invisible to JSON Schema). Mitigation: keep cross-boundary validation structural and state in CONTRACTS.md that a `refine` is never the sole guarantee of a boundary invariant; [S04.T12](../04-game-engine-core/T12-cli-job-protocol.md) diffs `serde` structs against the export and surfaces any gap.
- **Risk — placeholders mistaken for finished contracts.** Mitigation: each placeholder's `describe()` names the subtask that replaces it, and `ops`/`steps`/`expect` are `z.never()` arrays that cannot hold data.
- **Risk — strictness breaks the web when the api adds a field.** Mitigation: both sides parse with the same schemas from one repo and one version; an addition is a minor bump applied to both at once.
- **Question — one `CONTRACT_VERSION` for all contracts, or one per contract?** Recommendation: one, because the engine handshake is a single number and the repository ships as a unit. Revisit only if an external consumer appears (none is planned, D-007).
- **Question — where do the pure domain helpers live?** Their folders are reserved here; whether they ship as separate subpath exports is decided by [S02.T10](../02-card-data-and-search/T10-natural-language-parser.md) and [S03.T09](../03-tournament-meta-and-deck-builder/T09-decklist-parser-and-exporter.md).
